# GeoPulse V1 - Domain, invariants, distance and freshness

## Decisions

- Domain-first implementation in pure Python.
- Immutable value objects where appropriate.
- Geographic reference distance uses Haversine.
- Freshness age is computed exclusively from `observed_at`.
- Freshness V1 is piecewise: fresh, acceptable, stale, expired.
- Current time is injected into freshness evaluation.
- Provider thresholds override category thresholds.
- Ports are Protocols without concrete infrastructure implementations.
- V1 frontend uses local fixtures only.

## Demo

Backend:

    cd backend
    .venv/bin/python -m pytest tests/unit/domain -q
    .venv/bin/python -m pytest tests/property/domain -q

Haversine properties:

    cd backend
    .venv/bin/python -m pytest \
      tests/property/domain/test_distance_properties.py -q

Frontend:

    cd frontend
    npm start

Then open `/search`.

The page must show local fixtures covering:

- fresh
- acceptable
- stale
- expired
- known availability
- unknown availability

## Quality targets

- domain/models + rules: >=95% lines, >=90% branches
- domain/algorithms: >=95% lines, >=90% branches
- critical invariants have positive, negative and property-based tests
- no framework dependency in domain

## Known limitations

- No PostgreSQL/PostGIS implementation: V2.
- No REST search API: V3.
- No provider synchronization: V5.
- No Kafka implementation: V6.
- No Redis implementation: V7.
